# 后台与轮末维护（阶段 7）

只有 `memory.enabled=true` 才创建维护执行器；阶段 8 起默认开启。`memory.maintenance.enabled` 控制自动扫描，关闭后仍可显式执行手动维护。所有模型请求复用当前客户端，不创建额外模型配置。

## 自动触发

服务启动后立即扫描配置的 session-dir，之后按 `scan_interval_seconds` 扫描，默认 60 秒。首次未整理、有消息且不在前台修改的会话立即有资格；已整理会话须同时满足 dirty 和距离最后成功整理至少 `min_interval_hours`，默认 24 小时。整理元数据不增加 contentRevision，因而不制造 dirty。

后台只处理未覆盖的完整消息前缀，复用无工具 `MemoryModel` 的分片、预算和校验。空会话跳过；磁盘仍标记 RUNNING/CANCELLING 的快照可能属于其他进程，等待正常恢复，不猜测进程已退出。未完成工具尾块也等待正常会话恢复，不补造工具执行结果。正常退出不启动整理。

前台编码结果已保存后，在发布终态前串行检查新增 history 阈值（默认 5），满足时提炼一批。后台归档成功后也检查阈值；已归档会话即使已 clean，扫描仍会重试尚未提炼的历史。手动 consolidate 绕过阈值和自动退避，不绕过来源/版本/预算。

维护失败只记录独立日志，保留已保存的编码状态与结果。失败从 5 分钟开始指数退避，最多 1 小时；失败时间与成功整理时间分开。归档按会话退避，提炼按项目退避，避免同项目多会话立即重复失败请求。退避和进程内预约不跨重启持久化；成功时间、游标和候选已持久化。

## 并发与提交

单个维护执行器最多运行一个后台或手动任务，可与前台模型调用并发。进程内同项目提炼使用共享预约；其他进程通过存储 CAS 检测竞争。模型调用期间不持会话变更锁或文件锁。

归档前保存预期会话快照。提交时在短协调区再次检查：服务未关闭、该会话无活动前台写入、内存已发布状态和磁盘完整版本仍匹配、项目根未改变。失效快照直接放弃，不能覆盖前台新消息。归档复用 `SessionArchiveCoordinator`，将已提交元数据同步回已加载 Session，保持原 Context 引用；中断提交沿用原事务恢复与 CAS。

前台最终保存仍保持既有“已进入 FINISHING，取消编码已太晚”语义。轮末提炼使用独立 CancellationSource，取消维护或关闭不会把已完成编码改成取消/失败。关闭先取消前台与维护，在同一个五秒预算内等待退出，再关闭客户端；超时保持可重试关闭，不宣称资源已释放。失败的取消回调保留并在关闭时重试。

## 手动维护

```text
/memory compact
/memory consolidate
/cancel
```

手动任务返回 CompletionStage，终端不阻塞等待模型；同一服务只接受一个待执行手动维护请求。`/cancel` 可取消手动或轮末维护。compact 使用完整空闲快照；若提交前会话已变化，放弃该快照，原消息保留。

维护状态和工具行为通过隔离目录及脚本模型测试，不应为验证该功能自动调用真实模型 API。默认启用、专用验收、用量与恢复操作见 [运行说明](MEMORY_OPERATIONS.md)。
